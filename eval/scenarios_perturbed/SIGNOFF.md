# Semantic Perturbation Sign-off Ledger

Per `docs/evaluation/eval-framework.md` §4: every semantic-tier perturbation (LLM-drafted or
hand-authored) requires a **human sign-off** confirming it actually preserves (invariance family)
or changes as intended (sensitivity family) the meaning of its original, before it enters the
corpus — the human review is the real ground-truth authority, not the drafting itself.

One row per perturbed policy `.md` under `eval/scenarios_perturbed/`. `Source SHA256` is that file's
content hash — what the human actually read to sign off. `Digested SHA256` is the content hash of
its same-named counterpart under `eval/scenarios_digested/` — the file `digested_policy_path`
actually feeds the PRB in `test_policy_pipeline_robustness.py`, so an edit made only to the digested
copy (never touching the source prose) is just as much a corpus change as an edit to the prose
itself. `eval/test_semantic_signoff.py` fails loudly if either file's current hash no longer matches
its row, so an edited-but-not-resigned perturbation — in either form — can't silently ship.
Regenerate both hashes and get a fresh sign-off whenever either file changes.
